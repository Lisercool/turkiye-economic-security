# Економічна безпека країни — Туреччина

Навчальний сайт з аналізом економічної безпеки Туреччини за наданою теоретичною роботою. Автор: **Лошак Ю. О.**

**[Відкрити сайт](https://lisercool.github.io/turkiye-economic-security/)** · [Аналітика](https://lisercool.github.io/turkiye-economic-security/analytics.html) · [Методика](https://lisercool.github.io/turkiye-economic-security/methodology.html)

Репозиторій публічний. Сайт публікується через GitHub Pages із папки `site/` за допомогою GitHub Actions.

## Вміст сайту

- **Автор** — освіта, професійні інтереси, контактний телефон і опис дослідження.
- **Аналітика** — 9 рядів показників у 7 групах, 45 спостережень, таблиці, 7 інтерактивних графіків, порогові оцінки, загрози й висновки.
- **Методика** — формули, інтервали оцінювання, джерела та обмеження аналізу.
- **CSV** — повний набір даних із початковими величинами й оцінками.

Підтримуються вибір року, фільтр за рівнем безпеки, клавіатурна навігація й друк/PDF. Пропуски не замінюються значеннями інших років. Без JavaScript графіки та таблиці показані послідовно.

## Дані та методика

Числа і шкали зафіксовані за наданим документом «Аналіз економічної безпеки Туреччини», таблиці 1–15. У роботі джерелом статистики зазначено Світовий банк. Автоматичного завантаження нових даних немає.

Періоди рядів різняться: **2019–2023, 2020–2024 та 2021–2025**. Вони не зводяться до вигаданого спільного року чи інтегрального індексу. Рівень визначається до округлення: зокрема, торговельний коефіцієнт 2023 року 0,9450387… залишається небезпечним.

Дата вивантаження та нормативне першоджерело порогів у наданій роботі не вказані. Шкали не подаються як офіційні стандарти Туреччини або Світового банку.

## Як працює публікація

Workflow: [Deploy to GitHub Pages](https://github.com/Lisercool/turkiye-economic-security/actions/workflows/pages.yml), файл [pages.yml](.github/workflows/pages.yml).

Після кожного `push` у `main` автоматично виконуються:

1. Збірка HTML і CSV на Node.js 24.
2. Перевірка даних, порогів, експорту й сторінок — 8 тестів.
3. Публікація вмісту `site/` у GitHub Pages після успішних перевірок.

README, документація, тести, генератор та локальний сервер не входять до файлів сайту. Їхній код доступний у публічному репозиторії.

### Повторний деплой вручну

1. Відкрити вкладку **Actions** у репозиторії.
2. Вибрати **Deploy to GitHub Pages**.
3. Натиснути **Run workflow**, обрати `main` і підтвердити запуск.
4. Дочекатися успішного завершення `build` та `deploy`, після чого відкрити сайт.

У **Settings → Pages → Build and deployment → Source** має бути вибрано **GitHub Actions**. Для цього проєкту не потрібно обирати публікацію з `/docs` чи кореня гілки: файли сайту передає підготовлений workflow.

Документація: [GitHub Pages із власним workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Локальний запуск та зміни

Потрібен Node.js 22–24. Сторонніх залежностей немає.

```sh
node scripts/build.mjs
node --test tests/*.test.mjs
node server.mjs
```

Відкрити **http://127.0.0.1:4174/**. Зупинити сервер — `Ctrl+C`. Інший порт: `PORT=8080 node server.mjs`.

Профіль і дані: `site/assets/data.js`. Шкали: `site/assets/model.js`. Графіки: `site/assets/charts.js`. Шаблони: `scripts/build.mjs`. Стилі: `site/assets/styles.css`. Після змін шаблонів чи даних перегенеруйте сторінки та перевірте їх перед відправленням у `main`.

Альтернативні команди: `npm run build`, `npm test`, `npm start`. Поле `private` у `package.json` запобігає випадковій публікації npm-пакета і не визначає видимість GitHub-репозиторію.

## Обробка даних і перевірки

Власний код не додає аналітики, cookies, мережевих API чи записів до сховищ браузера. Зовнішній хостинг може обробляти технічні відомості про відвідування. Заголовки локального Node-сервера не слід вважати налаштуваннями GitHub Pages; у HTML зберігається окрема політика CSP.

Вхідні PDF, локальні знімки перевірки та конфігурації інших проєктів до репозиторію не включені.

Деталі: [відповідність ТЗ](docs/requirements.md), [перевірка даних](docs/data-audit.md), [перевірка реалізації](docs/verification.md).
